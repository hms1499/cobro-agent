Policy under test (portal "Call a contract" form, exported JSON): one `deny` rule on `call_contract` when `request.classification == decoded_contract_call` and any of `contract != USDT`, `method != approve`, `args[0] != 0xa9AA…35b3`. Selector: chains 1 and 42220, EVM, partner-owned wallets.

Other findings:
- Para 3.21 deprecates `paraModalConfig` (theme, auth methods, layout). Sign-in methods and branding are configured in the Developer Portal.
- `npx setup-para` only stubs optional connector packages in `node_modules`; it changes no tracked files.
- Para's REST `sign-transaction` accepts only transaction types 0 and 2, so CIP-64 (stablecoin gas) needs `sign-raw`, which bypasses Guardrails by design.
- A portal "Call a contract" Guardrail denies every other contract call. Even when enforced, it would block swaps on the Textile reactor. Production needs one JSON-authored policy that allows `approve(reactor)` on the four tokens and calls to the reactor.

## Decision

Treasury signer: **Para REST**. Rule: Para REST if checks 1, 2, 3 pass → they pass.
Guardrails: **executor only**. Rule: "Para + executor" only if check 4 passes → it failed. The executor's caps, contract allow-list and withdraw-to-personal-wallet check are the sole enforcement until a Para policy is shown to deny on a re-test.
Treasury gas: **CELO drip** (default). Rule: CELO drip unless check 5 passes AND the team accepts that sign-raw bypasses Guardrails. Check 5 passed, and with Guardrails not enforced, sign-raw loses nothing today. Switching treasury gas to USDT is a team decision for Plan 3. It would earn the "gas paid in stablecoins" point for treasury transactions too.
Sign-in: **Para email**. Rule: Para if check 6 passes → it passes.

## Follow-ups for Plan 2
- Add a `TreasurySigner` backed by `ParaRestClient` (sign-transaction for type-2 transactions, sign-typed-data for Textile `takerProof`), with `Idempotency-Key` on every signing call.
- Wallet sign-in uses the Para React SDK. The server verifies the JWT with `verifyParaJwt` + JWKS. Configure email-only sign-in and Cobro branding in the Para portal, not in code.
- Ask Para (support or Discord) why an active Development Guardrail is not applied to REST `sign-transaction` for app-owned wallets. Re-test with `SPIKE_GUARDRAIL=1` before Plan 3 turns on live conversions.
- Plan 3: write the production policy as JSON (allow reactor calls + `approve(reactor)` on USDT/USAT/wARS/wBRL; deny the rest), keeping executor checks as the primary guard either way.
- Plan 3 decision: treasury gas as a CELO drip, or USDT via sign-raw (CIP-64).
